# Plan — 가려진 보신각을 반투명 건물 뒤로 보여주기

작성일: 2026-09-16 · 상태: **1곳 재구성 시험 구현·배포 완료, 엄격 기하 검증은 미완료**

## 실행 결과 (초기 계획보다 우선하는 최신 상태)

- 사용자 후속 지시로 AI 배경 1회·보신각 스프라이트 1회를 실행했다. 총 $0.146075, 재시도 없음.
- 원본 지도는 유지하고 국소 `reveal_mask` 안에서만 재구성 배경+보신각과 보간한다.
  기본/복원 시 원래 픽셀로 돌아간다. 종로타워 및 변경 허용 영역 밖 픽셀 동일을 검증했다.
- 전경 불투명도는 25/45/65% 비교(초기45%), 전환200ms, reduced-motion 즉시 전환.
- 원본의 전경 군집을 국소 분리한 **부분 재구성 패치**다. 지적 경계에 따른 전체 건물 투명화가 아니다.
- 도감의 보신각에서 진입, 해제 중 유효 알파 클릭, 다른 장소 선택/빈 지도 클릭/복원 버튼으로 종료한다.
  모바일은 진입 시 상세 패널을 닫아 지도를 보여준다. 보신각 클릭이나 도감에서 다시 상세를 연다.
- P1 이름 있는 도형(index3405), 바닥 약25.5×20m, 추정 중심 `[1332.99,659.34]`를 사용했다.
  지면30m·건물15m는 가정이며 화면 수직 오차 최소 ±11px 가능. 스프라이트44×34px 균일 축소, bbox `[1311,635,1355,669]`.
  실측 높이·지붕 윤곽이 미확정이므로 ±5%/4px 엄격 판정을 합격 처리하지 않았다.
- 차량 구간은 이 패치와 겹치지 않는다. 현재 보행 중심선도 대상 외곽 북쪽으로 지나가며 보신각 뒤 통과를 설정하지 않았다.
  반투명 건물 뒤 차량/보행자의 연속 깊이 가림은 이번 시험으로 검증한 기능이 아니다.
- 공개 주소 데스크톱·모바일에서 진입/복원·투명도·reduced-motion, 기존 차량/비/도감 회귀를 확인했다.
- 생성/기하/비용/마스크: `prototype2/work/bosingak-reveal-20260916/`.
  화면: `prototype2/work/public-qa-20260916/`. 오프라인 통합: `prototype2/scripts/city_reveal.py`.
- 공개: https://pixel-city-beta-six.vercel.app · 이용조건 미확정은 [배포 기록](../DEPLOYMENT.md)에 구분했다.

아래는 초기 검토 당시 계획과 근거다. 미구현·보류 표현은 당시 상태를 뜻하며 위 실행 결과를 우선한다.

## 결론

가능하다. 다만 지금 지도는 대부분 한 장의 그림이므로 앞 건물의 투명도만 낮춘다고
그 뒤의 보신각이 나타나지는 않는다. **가려진 배경과 보신각을 별도로 준비한 뒤,
그 위에 앞 건물을 반투명하게 합성해야 한다.**

우선 보신각 한 곳을 대상으로 ‘가려진 명소 보기’ 모드를 시험한다.
도시 전체의 건물을 객체화하거나 3D 엔진으로 전환하는 작업은 이번 범위가 아니다.
정사영 카메라·축척을 유지하며, 보신각을 확대하거나 다른 위치로 옮겨 가림을 피하지 않는다.

## 현재 코드·자료에서 확인한 근거

- [LivingLayer](../../prototype2/web/pilot/living.js)는 `landmarks[]`, 독립 RGBA 이미지,
  알파 기반 클릭 영역, 개별 표시/숨김을 지원한다. 연속적인 투명도 제어는 아직 없다.
- [LabMap](../../prototype2/web/pilot/lab.js)은 `before` 배경 위에 독립 랜드마크를 그린다.
  현재 차량/보행 가림은 이진 마스크이며, 전체 객체를 함께 깊이순으로 그리는 구조가 아니다.
- 현재 `prototype2/assets/city_pilot/overlay.json`에는 종로타워만 독립 랜드마크로 있다.
  보신각과 이를 가리는 일반 건물은 독립 에셋으로 등록되어 있지 않다.
- `prototype2/work/city-alignment-20260916/bosingak.json`은 보신각 원본 윤곽이 가려져
  폭·높이를 측정할 수 없다고 기록한다. 반투명 연출을 추가해도 이 자료 부족은 별도로 해결해야 한다.
- 임시 투영점은 약 `[1336.3, 658.1]`이며 **지면 높이 30m를 가정한 값**이다.
  확정 접지점이나 출입구가 아니므로 그대로 승인 좌표로 사용하지 않는다.

## 권장 표현

기본 지도는 기존 모습 그대로 유지한다. 사용자가 도감의 보신각 상세에서
‘가려진 명소 보기’를 누를 때만, 확인된 앞 건물을 옅게 하여 보신각을 드러낸다.

- 최초 진입은 도감/장소 목록에서 제공한다. 완전히 가려진 건물을 직접 클릭해야만 열리게 하지 않는다.
- 앞 건물은 불투명도 30% / 45% / 60%를 비교하고, 45%를 초기 시험값으로 한다.
  이는 ‘45% 투명’이 아니라 **45% 불투명, 55% 투명**이라는 뜻이다.
- 전환은 약 200ms. reduced-motion에서는 즉시 전환한다.
- 보신각에는 선택 윤곽과 이름을 표시하되, 건물 자체의 스케일은 바꾸지 않는다.
- ‘원래 지도’ 버튼, 선택 해제 또는 다른 장소 선택으로 앞 건물 불투명도 100% 복원.
- 줌·드래그 중 모드가 깜빡이거나 선택이 해제되지 않게 한다. 모바일도 동일한 명시적 버튼을 사용한다.
- ‘가림 해제 보기 · 숨겨진 외관/배경은 재구성’임을 표시한다. 실제 투시 영상이나 실측 복원으로 설명하지 않는다.
- 상시 반투명, 단순 마우스 hover 자동 전환, 캐릭터 추적 자동 가림 해제는 후속 검토로 남긴다.

## 합성 구조

한 지역의 시험용 레이어 순서는 다음과 같다. 실제 가림 관계를 확인한 뒤 확정한다.

```text
아래: 앞 건물을 제거한 국소 배경(가려진 지면 등 재구성)
      보신각 독립 스프라이트
      보신각을 가리는 앞 건물 픽셀(선택 시 불투명도 감소)
위:   선택 윤곽·이름·날씨 효과
```

앞 건물 픽셀은 가능한 한 기존 최종 이미지에서 마스크로 분리해 유지한다.
앞 건물이 그대로 박혀 있는 원본 배경 위에 같은 건물만 반투명하게 다시 그리면
뒤의 불투명 건물이 남으므로 효과가 없다. 제거된 배경 레이어가 필수다.

작업 범위가 작을 때는 위 레이어로 만든 ‘가림 해제 패치’를 국소 영역에 합성할 수 있다.
기본 모드에서는 기존 최종 이미지를 그대로 사용하고, 모드 전환 때만 해당 영역을 교체한다.
전체 지도를 흐리게 하거나 전역 변형하는 방식은 사용하지 않는다.

건물 전체를 반투명하게 하려면 해당 건물 아래에 가려진 배경 전체를 준비해야 한다.
보신각 주변 일부만 복원할 수 있다면 ‘부분 투시 패치’ 후보로 구분하고,
건물 전체 투명화가 완료됐다고 표현하지 않는다. 복원 범위가 너무 크면 첫 시험을 멈추고 범위를 재검토한다.

## 단계별 실행 계획

### 1. 가림 관계·배치 근거 확인 — 유료 생성 없이

1. 기존 원본/최종 이미지의 보신각 주변을 확대해 앞 건물 후보와 정확한 실루엣을 표시한다.
2. 기존 건물 도형·고도·카메라 기록을 읽기 전용으로 대조한다. 다른 세션의 prototype1은 수정하지 않는다.
3. 보신각의 지붕 크기·방향·접지점은 가려지지 않은 참고자료와 지리 기준으로 별도 검증한다.
   현재 가려진 캡처를 치수 기준으로 삼지 않는다.
4. 필요하면 같은 카메라에서 가림 건물만 숨긴 참조 캡처가 가능한지 조사한다.
   해당 제어가 가능한 것으로 단정하지 않으며, 불가능하면 별도 사진/도형 자료를 사용한다.
5. 앞 건물이 하나인지 여러 개인지, 투명화 대상 밖의 수목·담장·다른 건물도 가리는지 확인한다.

산출물: 대상 영역, 앞 건물 마스크, 투영/축척 근거, 미확정 영역, 출처·이용조건 기록.
참고 사진의 원근을 지도에 그대로 옮기지 않는다.

### 2. 무과금 합성 프로토타입

1. 단순한 보신각 대체 도형과 시험 배경으로 레이어 순서·반투명 효과만 검증한다.
2. 앞 건물은 기존 이미지 픽셀을 분리한다. 건물 실루엣 밖은 변경하지 않는다.
3. 100% / 60% / 45% / 30% 불투명도 비교와 원래 지도 복원을 구현한다.
4. 이 결과를 실제 보신각 외관 완성본과 구분하여 표시한다.

통과 조건: 대상이 실제로 드러남, 앞 건물 윤곽 유지, 이중 건물/빈 구멍 없음,
모드 해제 시 원본 복원, 마스크 밖 픽셀 동일. 이를 통과한 다음 에셋 제작을 진행한다.

### 3. 보신각·가려진 배경 에셋 제작

- 보신각 투명 스프라이트와 앞 건물 제거 배경을 각각 준비한다.
- 공통 정사영 조건: heading 22.5°, pitch −30°, 100m당 128px를 기준으로 재검증한다.
- 배치는 균일 확대/축소와 평행 이동만 허용한다. 전단·원근 왜곡으로 억지 정합하지 않는다.
- 자료로 확정한 목표 폭·높이에 대해 ±5%, 접지점 오차 4px 이내를 잠정 수용 기준으로 둔다.
  측정 불가능한 항목은 합격 처리하지 않고 미검증으로 남긴다.
- 보신각 지붕·기둥·기단의 식별성, 다른 누각과의 혼동, 기존 그림에 남은 중복 외형을 검수한다.
- 가려진 배경은 AI 추정일 수 있다. 도로·출입구를 새로 만들어 실제 동선처럼 사용하지 않는다.

이 문서는 유료 생성 실행 승인이 아니다. 먼저 무과금 시험을 완료한 뒤,
배경 1회·스프라이트 1회·필요 시 국소 보정 1회 이내의 호출 계획과 비용 상한을 확정한다.
기존 닫힌 실행의 남은 예산을 재사용하거나 자동 재시도하지 않는다.
반투명 전환 자체는 Canvas에서 처리하며 클릭할 때 API를 호출하지 않는다.

### 4. 실제 지도 상호작용 연결

- 보신각은 기존 `landmarks[]`에 추가하고, 앞 건물은 관광 도감 대상과 별개의 가림 레이어로 관리한다.
- `revealTargetId`, `foregroundIds`, 검증된 합성 순서와 불투명도 상태를 별도로 기록하는 최소 형식을 설계한다.
  기존 `landmark`/`landmarks[]` 실행은 그대로 읽을 수 있어야 한다.
- 가림 해제 중에는 선택한 보신각의 유효 알파 영역을 클릭 가능하게 하고, 앞 건물이 클릭을 가로채지 않게 한다.
  기본 모드에서는 가려진 보신각의 전체 히트 영역이 앞 건물 클릭을 빼앗지 않게 한다.
- 현재 `hit()`는 뒤에서부터 검사하므로 화면 합성 순서와 클릭 순서를 함께 수정·검증한다.
- 차량·보행자를 반투명 건물 뒤로 통과시킬 경우 현재 이진 제거 마스크를 그대로 사용하면 완전히 사라진다.
  해당 동선이 겹치는 경우에만 객체 깊이와 가림 마스크의 알파를 일치시키는 처리를 추가한다.
  단순 전체 그리기 순서 변경은 다른 건물의 가림을 깨뜨릴 수 있으므로 피한다.
- 1차 시험은 보신각 1곳과 확인된 앞 건물만 다룬다. 자동차 자동 가림 해제나 도시 전체 투시 기능으로 확대하지 않는다.

### 5. 검증·산출물

- 데스크톱/모바일: 도감 → 가림 해제 → 지도 선택 → 원래 지도로 복원.
- 불투명도별 비교, 최대 100% 줌 및 축소, 드래그, reduced-motion, 탭 숨김/복귀.
- 앞 건물 제거 배경에 기존 건물이 남지 않았는지, 지붕/테두리 번짐과 복제 픽셀이 없는지 확인.
- 반투명 전환이 없는 기본 화면은 기존 최종 이미지와 동일하게 유지. 변경 허용 영역 밖 픽셀 비교.
- 가림 해제 중 종로타워 선택·차량·보행·비 효과가 회귀하지 않는지 확인.
- 차량/보행 동선과 겹치면 앞/뒤 상태별 가림 강도·그리기 순서 시험을 추가한다.
- 반복 전환 중 이미지 재요청·AI 호출 없음, 합성 레이어 캐시, 불필요한 렌더 루프 없음 확인.
- 최종 산출물: 기본/가림 해제 PNG, 전환 화면 기록, 마스크·배치 근거, 검수 결과, 실제 비용 기록.
