# 서울의 실제 시간·날씨를 반영하는 픽셀 지도

조사·합의일: **2026-09-14** · [지역 기획](seoul-pilot.md) · [랜드마크](landmarks.md)

## 1. 목표와 현재 상태

사용자는 직접 고르는 감상 모드보다 **서울의 현재 시간·날씨에 따라 풍경이 달라지는 경험**을 선택했다.
낮·노을·밤의 빛과 그림자, 비, 눈이 내리는 모습과 표면에 쌓인 눈을 기획 대상으로 한다.

조사 기준 커밋 `e897aa3`에서 시간대·비 버튼은 준비 중이다. 이전 남산 시험에는 지정 영역의 타워 조명이 있지만,
현재 기상·일출몰과 연동한 환경 효과는 구현된 것으로 기록되어 있지 않다.
근거: [기준 UI](../../prototype2/web/pilot/index.html), [기존 실험 안내](../../prototype2/docs/GUIDE.md).
링크 대상 코드는 후속 작업으로 바뀔 수 있으므로 현재 상태를 확인할 때 기준 커밋과 비교한다.

이번 조사는 공식 데이터의 제공 여부와 표현 가능성을 확인했다. 회원가입·키 발급·인증 API 호출·실시간 연동은 수행하지 않았다.

## 2. 데이터와 표현의 연결

| 표현 | 근거 데이터 | 기획상 연결 | 해석의 경계 |
|---|---|---|---|
| 낮·노을·밤 | 서울 시각, 일출·일몰·박명 | 계절에 맞춰 밝기와 색온도를 바꾸고 밤에 조명 표현 | 실제 하늘색·건물 점등 상태를 측정한 것은 아님 |
| 그림자 변화 | 날짜·좌표·태양 방위각/고도 | 방향·길이의 변화를 근사 표현 | 건물·지형·가림을 정확히 재현하려면 추가 정보 필요 |
| 맑음·흐림 | 운량·하늘 상태 | 직사광과 대비를 조절 | 강수 없음이 맑음을 뜻하지 않음 |
| 비·진눈깨비·눈 | 강수 형태, 강수량, 기온 | 서로 다른 입자, 강도와 속도 연출 | 강수확률을 현재 강수로 사용하지 않음 |
| 바람 | 풍향·풍속 | 빗줄기·눈송이의 기울기와 이동 | 관측 지점 바람이 건물 사이 돌풍을 재현하지는 않음 |
| 쌓인 눈 | 적설·신적설 관측 | 지붕·수목·지면의 적설 표현 단계 | 관측소 적설량이 각 표면의 실제 적설량은 아님 |
| 젖은 표면 | 현재·최근 강수 | 바닥의 어두워짐·반사·물결 연출 | 건물별 배수·표면 습윤 관측이 아닌 시각적 해석 |

실제 데이터는 **표현 상태의 근거**로 사용하고, 픽셀 그림은 그 상태를 해석한다.
지도에 보이는 물웅덩이·눈의 두께·건물 조명을 현장 측정값처럼 설명하지 않는다.

## 3. 공식 자료 조사

모든 자료의 확인일은 **2026-09-14**다.

### 기상청 단기예보 조회서비스

[공공데이터포털 서비스 안내](https://www.data.go.kr/data/15084084/openapi.do)

초단기실황·초단기예보·단기예보를 제공한다. 공식 안내는 5km 격자를 사용하며, 초단기실황이
예보 구역의 대표 AWS 관측값임을 설명한다. 이번 1.65㎢ 지도에 건물별로 독립된 실황이 제공된다고 가정하지 않는다.

현재 강수·기온·바람은 초단기실황을 우선 검토한다. 자료구분코드와 각 값의 의미는
공식 최신 활용가이드에 대조해야 한다. 조회 입력은 날짜·발표 시각·격자 X/Y 및 인증키다.
공식 페이지의 참고문서 표시는 `기상청41_단기예보 조회서비스_오픈API활용가이드_2607.zip`이다.
이번에는 이 압축파일을 내려받아 전체 코드표·발표 지연·결측 규칙을 검증하지 않았다.

후속 확인: 선정 지역 중심을 공식 방식으로 격자 변환, 경계의 격자 걸침 여부,
실황의 발표·이용 가능 시각, 강수 형태 코드, 운량의 관측/예보 출처 구분, 응답 결측·오류 처리.

### 기상청 ASOS와 적설

[기상청 API허브 지상관측 명세](https://apihub.kma.go.kr/apiList.do)

공식 시간자료 명세에는 다음 항목이 있다.

| 항목 | 의미 | 기획 활용 |
|---|---|---|
| `TM`, `STN` | 관측시각·관측지점 | 근거 시각과 지점 표시 |
| `TA`, `WD`, `WS` | 기온·풍향·풍속 | 입자와 환경 상태 참고 |
| `RN`, `RN_INT` | 강수량·강수강도 | 강수 표현 참고; 값의 시간 범위 구분 필요 |
| `SD_HR3` | 3시간 신적설(cm) | 최근 새로 내린 눈 |
| `SD_DAY` | 일 신적설(cm) | 해당 일에 새로 내린 눈 |
| `SD_TOT` | 적설(cm) | 현재 쌓인 눈 표현의 대표 신호 |
| `CA_TOT` | 전운량 | 직사광·대비 조절의 관측 후보 |

서울 관측지점 **108**의 위치는 경도 126.9658, 위도 37.57142로 공개되어 있다.
선정 구역 인근의 적설 대표 자료 후보로 삼되 각 랜드마크의 현장 관측으로 취급하지 않는다.
[기상청 지점 자료](https://datawiki.kma.go.kr/doku.php?id=%EA%B8%B0%EC%83%81%EA%B4%80%EC%B8%A1%3A%EC%A7%80%EC%83%81%3A%EC%9E%90%EB%8F%99%EA%B8%B0%EC%83%81%EA%B4%80%EC%B8%A1_aws)

항목이 명세에 있다는 것과 모든 시각에 유효한 값이 있다는 것은 다르다.
해당 지점·요소의 관측 주기, 지연, 결측·무현상 코드와 실제 겨울철 응답은 후속 검증이 필요하다.

### 한국천문연구원 출몰시각

[공공데이터포털 출몰시각 정보](https://www.data.go.kr/data/15012688/openapi.do)

날짜·지역 또는 위치에 따른 일출·일몰과 시민박명 등 해달 출몰 정보를 제공한다.
서울 시간대는 `Asia/Seoul`을 기준으로 삼고, 겨울과 여름을 고정 시각의 낮·밤 경계로 처리하지 않는다.
일몰 전후 어느 구간을 노을로 표현할지와 전환 속도는 미감 조정값으로 분리한다.
실제 붉은 노을의 발생 여부까지 이 데이터가 보장하지는 않는다.

### 태양 위치와 2D 조명

[Solar Position Algorithm](https://midcdmz.nlr.gov/spa/)은 날짜·시각·위치에 따른 태양 천정각과 방위각을
계산하는 참고 자료다. 일출·일몰 시각만으로는 하루 중 그림자의 방향과 길이를 정할 수 없다.
이 알고리즘의 코드나 라이브러리를 이번에 채택·설치한 것은 아니다.

[Godot 공식 2D 조명 설명](https://docs.godotengine.org/en/stable/tutorials/2d/2d_lights_and_shadows.html)은
이미지의 조명, 그림자를 만드는 가림 형상, 표면 방향 정보가 서로 다른 역할임을 보여준다.
이는 표현 원리의 참고 자료이며 엔진 변경 제안이 아니다. 현재 Canvas 환경의 실제 구현 방식은 후속 검토 대상이다.

## 4. 모든 건물을 개별 생성하지 않고 환경을 표현하는 방법

아래는 구현 완료 사항이 아닌 **제작 구조 제안**이다.

| 구성 | 준비할 정보 | 기대 역할 |
|---|---|---|
| 일반 도시 배경 | 고정 이미지와 정합된 지붕·수목·지면 구분 | 넓은 영역의 색조·젖음·적설 표현 |
| 8개 랜드마크 | 독립 이미지, 접지점·선택 영역·표면 구분 | 중요한 외형 보존, 세밀한 적설·조명 |
| 공간정보 | 위치·높이·지형·도로·대표 가림 형상 | 효과 영역과 그림자의 보조 기준 |
| 환경 상태 | 관측 시각·지역·시간·강수·적설 등 | 같은 장면의 상태 변화 |

효과용 영역을 미리 준비하면 지도 조작·날씨 갱신 때 이미지를 다시 AI 생성할 필요가 없다.
AI 생성비는 줄일 수 있지만 영역 제작·정합·검수 비용이 남는다. 그 비용을 확인하기 전 전체 효과가 싸거나
자동화되었다고 단정하지 않는다.

### 그림자: 기존 그림 속 그림자부터 다룬다

현재 생성 이미지에는 이미 특정 방향의 밝기와 그림자가 포함된다. 그 위에 방향이 바뀌는 그림자를 덧그리면
두 그림자가 동시에 남을 수 있다. 후속 배경 제작 시 강한 투영 그림자를 어떻게 분리·완화할지 먼저 검토한다.
랜드마크는 효과를 검토하기 쉬운 자료로 준비하고, 일반 건물은 정합된 보조 정보가 확보된 범위에서 근사한다.

표면 방향을 나타내는 정보만으로 다른 건물에 드리우는 그림자까지 해결되지 않는다.
태양 방향·높이·가림과 실제 그림 사이의 정합이 필요하다. 초기 목표는 실제 시간에 따른 일관된 변화이며,
도시 전체의 정밀 일조 분석은 제품 주장에 포함하지 않는다.

### 눈: 강설과 적설 상태를 분리한다

눈송이는 공중의 움직임이고, 적설은 표면의 상태다. 건물 외벽·창문·연못까지 일괄적으로 흰색 처리하지 않고
지붕·수목·지면별로 표현 가능한 영역을 준비한다. 눈이 그쳐도 유효한 적설 관측값이 남으면 적설 표현을 유지할 수 있다.

눈이 내린다는 이유만으로 일정 시간마다 적설량을 무한히 더하지 않는다.
관측 적설이 없으면 임의 누적값을 실제 관측처럼 표시하지 않으며, 녹는 속도·제설·지붕별 눈 두께는
별도 근거 없는 세부 시뮬레이션으로 확장하지 않는다. 기존 적설과 새 강설의 전환은 유효한 관측·자료 시각을 기준으로 설계한다.

## 5. 사용자 경험과 자료 누락

기본 진입 상태는 서울의 현재 환경이다. 사용자 기기의 해외 시간대를 그대로 서울 풍경에 적용하지 않는다.
지도에는 대표 지역·관측 기준 시각을 확인할 수 있는 간결한 표시를 둔다. 날씨 변화는 장소 선택·지도 이동을 초기화하지 않는다.

기획 기본 원칙은 다음과 같다. 정확한 갱신 간격·유효기간은 제공 주기와 실제 응답 확인 후 정한다.

- 관측 자료와 예보 자료의 기준 시각·출처를 구분한다.
- 강수 없음, 흐림, 자료 없음은 서로 다른 상태로 취급한다.
- 관측이 지연되면 마지막 값의 시각과 지연 상태를 알린다. 오래된 상태를 현재 실황으로 표시하지 않는다.
- 사용할 자료가 없으면 자료 없음 상태를 보여주며 임의의 맑음·적설 0을 만들어내지 않는다.
- 강우·강설·조명 애니메이션은 지도·장소 정보를 가리지 않으며 움직임 줄이기 설정을 고려한다.
- 실제 서울 환경이 기본이다. 시연용 수동 변경을 추가한다면 ‘미리보기’로 구분하고 실황 복귀 동작을 둔다.
  미리보기 기능 자체는 이번에 확정한 필수 기능이 아니다.

키 발급과 인증 호출은 후속 연동 단계에서 수행한다. 날씨 조회와 표시 사이에 공유 가능한 캐시를 두는 방향을 검토하되,
서버 구성·배포·구체적 API 인터페이스는 이번 문서에서 확정하지 않는다.

## 6. 후속 검증 시나리오

| 상황 | 확인할 결과 |
|---|---|
| 여름과 겨울의 같은 서울 시각 | 날짜별 일출몰 차이에 맞는 환경 상태 |
| 맑은 낮 → 노을 → 밤 | 색조·그림자·조명이 일관되게 바뀌며 기존 그림자가 중복되지 않음 |
| 비가 없고 흐린 낮 | 강수 없음만으로 맑음 처리하지 않음 |
| 비 → 진눈깨비 → 눈 | 자료의 강수 형태에 맞는 표현, 강수확률과 혼동하지 않음 |
| 강설 종료, 적설 관측은 유효 | 눈송이는 멈추고 표면의 눈은 남을 수 있음 |
| 적설 값 결측 | 0cm 또는 임의 누적 적설로 바꾸지 않음 |
| API 지연·실패·날짜 변경 | 기준 시각·자료 상태가 정직하게 표시되고 서울 날짜로 조회 |
| 휴대기기의 해외 시간대 | 지도는 서울 시각을 기준으로 표현 |
| 눈·야간 상태에서 장소 선택 | 랜드마크 식별성과 선택 영역 유지 |
| 축소·확대·낮은 성능·움직임 줄이기 | 픽셀 크기·표면 정합·가독성 유지, 과도한 움직임 억제 |

이 표는 향후 기능 검수 기준이며 이번에 실행한 테스트 목록이 아니다.
