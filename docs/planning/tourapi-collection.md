# TourAPI 로컬 수집

광화문권 관광 데이터의 해설·장소 추천 활용성을 조사한다. 앱·챗봇에는 연결하지 않는다.

## 실행

Python 3.9 이상과 시스템 `curl`을 사용한다. 키를 설정한 같은 터미널에서 실행한다.

```sh
export TOUR_API_SERVICE_KEY='발급받은 키'
python3 scripts/collect_tourapi.py --output-dir '/원하는/데이터/기준폴더'
```

Encoding/Decoding 키를 모두 지원한다. URL 디코딩을 한 번 적용한 뒤 요청을 구성할 때 인코딩한다.
키를 명령 인자나 파일에 기록하지 않으며, curl 요청 URL은 표준입력으로 전달한다.
인증서 검증은 유지한다. 이 환경의 Python 인증서 오류 때문에 전송에는 시스템 curl을 사용한다.

이번 저장 위치는 사용자가 지정한 **Google Drive의 projects/pixel_city 폴더**다. Git 저장소 밖에
위치하므로 원본 데이터를 위해 저장소의 `.gitignore`를 변경할 필요는 없다. 개인 계정이 포함된
절대 경로는 스크립트에 내장하지 않는다.

## 범위와 산출물

- 경계: 서 126.971, 남 37.568, 동 126.984, 북 37.581.
- 중심 (126.9775, 37.5745), 반경 1.2km 위치 검색 후 좌표로 경계 내 표본을 선별한다.
- 광화문·근정전·경회루·세종대왕동상·이순신장군동상·세종문화회관·보신각·종로타워를 검색한다.
- 상위 시설 대응을 확인하기 위해 경복궁도 검색한다.
- 랜드마크 후보와 경복궁을 우선하고, 관광지·문화시설·음식점에서 각 최대 10곳을 추가한다.
- 주변 표본은 중심과의 근사 직선거리순, 동률이면 콘텐츠 ID순이다. 인기 순위가 아니다.
- 키워드 검색 원본에는 경계 밖 장소도 포함된다. 상세 표본 선정은 경계 안으로 제한한다.
- 구 지역·분류코드가 빈 항목을 누락하지 않도록 위치·키워드 조회에는 구 코드 필터를 넣지 않는다.
  유형별 표본은 수집 결과의 콘텐츠 유형으로 구분한다.
- 좌표는 원문을 보존하며 출입구 좌표라고 간주하지 않는다. 이름 검색 후보는 사람이 확인한다.

각 실행은 기준폴더 아래 `tourapi/<수집시각>/`에 다음을 저장한다.

| 산출물 | 내용 |
|---|---|
| raw/ | 요청별 응답. 혹시 응답에 포함된 인증키 값은 제거 |
| catalog.json | 목록·키워드 검색을 콘텐츠 ID로 통합한 자료 |
| places.json | 상세 표본의 목록 원문과 공통·소개·반복 정보 |
| landmarks.json | 랜드마크별 검색 후보와 검토 상태 |
| requests.jsonl | 키를 제외한 요청 조건, HTTP/API 상태, 요청별 소요시간 |
| manifest.json | 수집시각·범위·완료 상태·실패 내역 |
| report.md | 표본 목록과 정보 제공 여부, API별 시간 통계 |

최대 200회 호출(재시도 포함), 요청당 20초, 일시 오류 최대 2회 재시도.
인증·일일 할당량 오류는 중단하며, 중단 시 확보한 데이터를 보존한다. 종료코드 0은 완료,
2는 일부 실패·중단이다. 사진은 응답에 제공되는 URL과 이용조건 코드만 보관한다.

## 검토 기준

소개문·운영시간·휴무·요금 등은 실제 응답에 있는 범위에서 사용한다. 누락값을 추정하지 않는다.
현재 영업 여부·실내 여부·체류시간·보행 경로는 별도의 근거가 필요하다.
서버의 수정시각과 이번 수집시각은 서로 다르며, 운영 공지의 최신성 보장은 아니다.
응답시간은 이 환경의 표본 측정이며 챗봇 생성 시간·사용자 대기시간을 포함하지 않는다.

검증: `python3 -m unittest discover -s scripts -p 'test_collect_tourapi.py'`

출처: [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do)

229건은 전국 키워드 검색 결과와 상업·행사 등 다른 유형을 포함한다. 89건 역시 관광지·문화시설·음식점만의

HTTP 시간에는 순차 요청 사이의 대기, 재시도 대기, 모델 생성, 사용자 화면 표시 시간이 포함되지 않는다.

운영시간 필드에 값이 있다는 것과 시간표를 계산할 수 있다는 것은 다르다. 예를 들어 세종문화회관은
운영시간·휴무·요금이 **공연 및 전시별로 상이함**으로 제공된다. 현재 관람 가능 여부를 자동 확정할 수 없다.

측량하거나 검증했다는 뜻은 아니다. 원문 좌표는 면적이 넓은 시설의 대표 위치일 수 있다.

### 데이터 수급 과정에서 확인한 사항

1. **구 지역코드 필터 누락:** 경복궁·광화문·광화문광장은 `areacode`가 비어 있고
   `lDongRegnCd=11`로 제공된다. `areaCode=1` 검색에서 빠졌지만 그 필터를 제거하자 확인됐다.
   수집 도구는 구 코드 조건 없이 검색하고 좌표와 콘텐츠 유형으로 표본을 선별하도록 수정했다.
2. **공통 조회의 매개변수:** `detailCommon2`에 `contentTypeId`를 넣으면 HTTP 200이어도
   최상위 `resultCode=10`으로 거부됐다. 해당 매개변수를 제거해 34건을 보완했다. 초기 오류 응답과
   보완 요청은 원본 및 호출 기록에 남겼고, 스크립트는 같은 매개변수 오류가 발생하면 즉시 중단한다.
3. **동명 장소:** ‘경회루’ 음식점, ‘한복남 경복궁점’을 궁궐 건물·상위 시설로 연결하지 않았다.
4. **정보의 한계:** 경복궁 전체 정보로 근정전·경회루 각각의 상세 해설을 충분히 대체할 수는 없다.

### 챗봇 기획에 적용할 판단

- **우선 가능:** 선택한 장소 소개, 제공된 관람 정보의 원문 안내, 지도 범위 안의 장소 유형 검색.
- **검수 후 가능:** 비 오는 날 실내 장소 추천, 짧은 산책 코스 추천. 실내 여부·체류시간·출입구 정보를 보완해야 한다.
- **추가 소스 필요:** 종로타워 해설, 궁궐 개별 전각의 자세한 해설, 오늘의 공연·임시 휴관, 실제 보행 경로.
- **응답 구성:** 관광 정보를 미리 확보하고, 대화에서는 필요한 장소 자료만 골라 설명하는 방식이 타당하다.
  이번 수치만으로 운영 환경의 지연시간이나 SLA를 보장하지 않는다.

- 데이터는 Git 저장소 밖에 저장함. 앱·지도·챗봇 코드는 이 수집 작업에서 변경하지 않음.
