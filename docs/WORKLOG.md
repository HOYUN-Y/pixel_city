### 발견된 제약 (중요)

1. **`buld_se_cd`가 전부 `'0'`, `poi_chk`가 전부 `null`.**
   → **이 레이어만으로는 용도(주거/상업/문화재) 구분이 불가능하다.**
   용도별 스프라이트 매핑을 하려면 **국토부 GIS건물통합정보가 반드시 필요**하다.
   APPROACH.md의 A안이 전제한 "용도 속성으로 자동 매핑"은 이 데이터 확보에 달렸다.
2. **실측 높이가 없다.** 층수만 있어 `FLOOR_H = 3.0m`로 가정했다. `iso.py`에 상수로 빼뒀다.
3. **0층 건물이 50동(17%).** 부속건물로 보이며 1층으로 올려 처리했다.
4. **궁궐 전각이 납작한 상자로 나온다.** APPROACH.md §5에서 예측한 그대로 재현됐다.
   → 스프라이트 보강 없이는 경복궁이 "낮은 베이지 상자 밭"이다.
5. **WFS는 bbox에 걸친 피처 전체를 반환한다.** 경복궁 지정구역 폴리곤이 bbox 밖까지 뻗어
   자동 프레이밍이 끌려갔다. 프레임을 bbox로 고정하도록 고쳤다 (타일링에도 이 방식이 맞다).

## 2026-09-03 — GIS건물통합정보 확보 경로 정정

- **정정**: 앞 기록에서 "GIS건물통합정보는 공공데이터포털에서 받아야 한다"고 적었는데,
  **V-World에도 있다.** 다만 **오픈API가 아니라 다운로드 서비스**로 제공된다.
- **확인 방법**: V-World 엔드포인트 3개를 모두 조회했다.
  - WFS `/req/wfs` — 177개 레이어. 건물 관련은 `lt_c_spbd`, `lt_c_ud610`, `lt_c_ud620`뿐
  - WMS `/req/wms` — 동일 177개. 건물 관련 `lt_c_spbd` 하나
  - 데이터API `/req/data` — 동일 카탈로그. `LT_C_SPBD` 속성이 10개로 **WFS(24개)보다 적다**
  → **오픈API 카탈로그에는 GIS건물통합정보가 없다.** 이건 사실이다.
  → 하지만 V-World **다운로드 서비스**에는 있다 (`건물통합정보 마스터`, vworld_open_30524).
- **결론 (실무상 차이 없음)**: 어느 쪽이든 로그인 후 **파일로 받아야** 한다.
  - V-World: vworld.kr 로그인 → 데이터 검색 "건물통합정보" → 신청·다운로드
  - 공공데이터포털: `data.go.kr/data/15083092/fileData.do` (SHP)
- **왜 필요한가**: `lt_c_spbd`는 `buld_se_cd`가 전부 `'0'`, `poi_chk`가 전부 `null`이라
  **용도 구분이 불가능**하다. 건물통합정보에는 건축물대장(세움터) 속성이 붙어 **용도·높이**가
  들어온다. APPROACH.md A안의 "용도별 스프라이트 자동 매핑"이 이 데이터에 달려 있다.
- **부수 확인**: 데이터API는 WFS보다 속성이 적으므로 **WFS를 쓴다.**

## 2026-09-03 — Phase 0 PoC v2: 용도별건물정보로 한옥 자동 판별 성공
