## 차량 시험과 한계

첫 후보 도로는 우상향14도였지만 차량 생성물은 우하향/좌상향 약20~25도로 나왔다.
재생성 없이 다른 그림 도로를 선정했다. 새 경로는 중심 약(774,903), 우하향 약28도이며
x=768의 신규/기존 경계를 넘는다. 차선당2대, 총4대, 속도28px/초, 최대14px 스프라이트다.
저알파 주변광은 알파128 임계값으로 제거했고 실제 화면에서 도로 위 방향/크기를 확인했다.

짧은116px 안팎의 직선 시험이며 끝점에서 페이드 후 반복한다. 실제 도로명·통행방향·차량 크기·교통을 보증하지 않는다.
선정 구간에 확실한 상부 가림 물체를 지정하지 않았으므로 **차량 가림은 이번 시험의 검증 성과가 아니다**.
기존 보행자의 타워 기단 완전가림은 유지했다. 타워는 선택/강조만 되며 새 독립 랜드마크 생성은 제외했다.

## 원본 품질과 사용자 후속 요청

최초에는 위쪽 행의3D 건물 누락 때문에 생성 전에 중단했다.
사용자가 “AI생성까지 진행하고 나는 조금이따가 확인해볼게”라고 요청한 뒤,
부족한 높이·외관은 **AI 추정인 실험**이라고 안내하고 생성했다.
이는 원본의 완전성이나 결과의 미감 승인이 아니다. `user_visual_approval=false`를 유지한다.

원본 부모는 `20260914T091414062775Z`, 확장 캡처는 `20260914T125937359608Z`다.
고정 월드 카메라를 화면평면 왼쪽300m·위쪽700/3m 이동, 정사영 폭2000m·1920² DPR1로 촬영했다.
2560² 변환 뒤 사방128px를 제외한다. 9개 기준점 최대 대응오차 약9.06e-10px,
깊이3곳 모두100m=원본96px/최종128px로 **입력 투영** 검증을 통과했다.

정사영 직접 촬영, 최소60초 대기, 광각 원근 사전 로딩, 구역별/지표면 중심 사전 로딩을 시도했다.
지표면 선택은 투영 전환 후2프레임 동기화로 고쳤으나 위쪽 외관 누락은 지속했다.
서비스 데이터 범위와 SDK 로딩/상세도 중 원인은 확정하지 못했다.
사전 로딩의 원근 화면은 생성 입력으로 쓰지 않았고, `globe.tilesLoaded`를 외관 완전성으로 간주하지 않았다.
[원본 진단 이력](../eval/vworld/projection_expand/index.html)은 따로 보존했다.

생성 전5칸 각각 도로2점·지붕너비1개를 고정했지만, 생성 후 대응을 자신 있게 측정하지 못한 항목은
모두 누락 처리했다. **도로≤8px·건물너비±15%는 미통과**다. 입력의 정사영 검증이나 보기 좋은 전체 그림이 이를 대신하지 않는다.
위쪽 건물 높이와 벽면은 실제 서울의 복원이 아니다.
