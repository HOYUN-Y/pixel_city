# prototype2 관리·감독 지침

> 작성일: 2026-09-04  
> 적용 범위: `prototype2/` 전체  
> 역할 구분: **Claude가 구현하고, Codex는 검토·감독한다.**  
> 이 문서는 구현 계획이 아니라 구현 과정과 결과를 어떤 기준으로 감독할지 정의한다.

## 1. 감독의 목적

감독의 목적은 구현을 대신하거나 취향으로 방향을 흔드는 것이 아니다. 다음 세 가지를 지킨다.

1. prototype2가 해결하려는 문제인 **참고 픽셀 지도와의 시각적 차이**가 실제로 줄었는지 확인한다.
2. 보기 좋은 결과를 얻는 과정에서 공간 구조·재현성·라이선스·마감이 무너지지 않도록 한다.
3. 성공과 실패를 모두 근거와 함께 남겨 공모전 제출 문서에서 과장 없이 설명할 수 있게 한다.

## 2. 역할과 권한

### Claude — 구현 담당

- 계획에 따른 코드 작성, 실행, 모델 추론, 산출물 생성과 검증을 담당한다.
- 프롬프트·모델 설정·seed·실행 환경·비용을 기록한다.
- 진행하면서 생긴 기술적 판단과 계획 변경을 문서에 남긴다.
- 기존 `poc/`와 `web/`을 보호하고 prototype2 작업을 별도로 유지한다.

### Codex — 감독 담당

- 기본적으로 파일과 결과물을 **읽고 검토한다.**
- 요청받지 않은 구현, 리팩터링, 모델 실행, 파일 덮어쓰기를 하지 않는다.
- 변경 diff, 실행 기록, 이미지 결과, 평가표를 근거로 판정한다.
- 문제를 발견하면 위치·영향·수정 조건을 제시한다.
- 수정이 필요해도 Claude의 진행 중 작업을 직접 고치지 않고 먼저 사용자에게 보고한다.
- 사용자가 명시적으로 수정 구현을 요청한 경우에만 코드나 산출물을 변경한다.

### 사용자 — 최종 결정권자

- 시각적 선호와 최종 채택 여부를 결정한다.
- GPU 계정·결제·외부 서비스 가입 등 본인 권한이 필요한 작업을 수행한다.
- 감독 의견이 구현 계획과 충돌할 때 어느 방향을 채택할지 결정한다.

## 3. 감독 기본 원칙

### 3.1 진행 중 작업을 방해하지 않는다

- 사용자가 “확인만” 요청하면 읽기 전용 검토만 한다.
- Claude가 수정 중인 파일을 동시에 편집하지 않는다.
- 테스트나 스크립트 실행이 생성물을 덮어쓸 가능성이 있으면 실행하지 않는다.
- 작업 중간 상태의 미완성 코드를 완성본처럼 판정하지 않는다.

### 3.2 계획보다 근거를 본다

- 체크박스가 완료되어 있어도 산출물과 실행 근거가 없으면 완료로 인정하지 않는다.
- 이미지 품질은 설명문이 아니라 실제 결과 이미지로 판단한다.
- 구조 보존은 “유지하도록 프롬프트했다”가 아니라 원본과의 중첩 비교로 확인한다.
- 재현성은 설정 기록뿐 아니라 같은 설정의 반복 실행 결과로 확인한다.

### 3.3 미감과 정확성을 분리한다

- AI 배경은 시각적 해석이며 실측 공간데이터로 간주하지 않는다.
- POI·지하철·관광 경로는 원본 좌표를 유지해야 한다.
- 배경 이미지가 이동시킨 건물과 실제 좌표 마커가 크게 어긋나면 결함으로 기록한다.
- “예쁘다”와 “같은 장소다”를 별도 평가 항목으로 유지한다.

### 3.4 마감이 기술적 욕심보다 우선한다

- 공모전 문서 작성 기간인 09-16~17을 침범하는 구현 확대를 승인하지 않는다.
- 대표 장면이 통과하기 전에 범위 확대·LoRA·다중 타일 문제로 넘어가지 않는다.
- 실패 조건에 도달하면 같은 방식의 반복 시도를 중단하도록 권고한다.

## 4. 문서 우선순위

계획 문서가 충돌하면 임의로 해석하지 않고 충돌을 보고한다. 정리 후 우선순위는 다음과 같다.

1. 사용자의 최신 명시적 지시
2. `docs/AGENTS.md`의 저장소 공통 규칙
3. `prototype2/README.md`의 목표·성공 기준·금지사항
4. `prototype2/PLAN.md`의 현재 실행 범위와 순서
5. 코드 주석과 작업 중 메모

`README.md`와 `PLAN.md`의 내용이 의도적으로 다르면 PLAN에 변경 이유와 적용 기간을 적고,
README의 해당 항목에도 축소 또는 보류 상태를 표시해야 한다. 한 문서가 다른 문서를 우선한다고
선언하면서 실제 내용이 반대인 상태는 허용하지 않는다.

## 5. 검토 시점과 게이트

모든 커밋이나 작은 수정마다 개입하지 않는다. 아래 게이트에서 묶어서 검토한다.

### Gate 0 — 실행 전 계획 검토

확인할 것:

- [ ] 목표 산출물과 중단 조건이 명확한가
- [ ] 기준 구간·bbox·카메라·해상도가 고정되었는가
- [ ] 기존 프로토타입을 덮어쓰지 않는가
- [ ] 모델 및 GPU 실행 경로의 라이선스 확인 단계가 있는가
- [ ] 실제 지원되지 않는 모델 파라미터를 가정하지 않았는가
- [ ] 일정이 `docs/PLAN.md`의 본 트랙과 동시에 수행 가능한가

### Gate 1 — 조건 이미지 검토

확인할 것:

- [ ] RGB·edge·height/depth·semantic mask의 크기가 같은가
- [ ] 네 이미지의 카메라와 픽셀 좌표가 완전히 일치하는가
- [ ] edge에 가려진 은선이나 중복 경계가 과도하게 남지 않았는가
- [ ] height가 저층 건물을 구분할 수 있는 명암 범위를 갖는가
- [ ] semantic class와 색상 ID가 문서화되었는가
- [ ] `camera.json`만으로 POI를 같은 위치에 재투영할 수 있는가
- [ ] 생성 스크립트를 다시 실행해 같은 결과를 만들 수 있는가

판정: 조건 이미지가 어긋나면 모델 추론으로 넘어가지 않는다.

### Gate 2 — 모델 실행 전 권리·재현성 검토

확인할 것:

- [ ] 정확한 모델명·버전·가중치 출처가 기록되었는가
- [ ] 모델 라이선스 원문 링크와 적용 조건이 기록되었는가
- [ ] GPU 또는 추론 서비스의 별도 약관을 확인했는가
- [ ] 출력물의 공모전 제출 가능 여부를 설명할 수 있는가
- [ ] 출력물을 후속 학습에 쓸 수 있는지 구분했는가
- [ ] 프롬프트·negative prompt·seed·스텝·해상도·입력 순서가 저장되는가
- [ ] 계획한 조건 강도나 denoise 값이 해당 파이프라인에서 실제 지원되는가

판정: `LICENSES.md`와 실행 설정이 없으면 본 추론 결과를 채택 후보로 인정하지 않는다.

### Gate 3 — 단일 장면 결과 검토

최소 통과 조건:

- [ ] 기존 렌더보다 시각적 밀도와 매력이 명확히 좋아졌다.
- [ ] 주요 도로의 위치·방향·연결이 유지된다.
- [ ] 경복궁 영역과 주요 전각 배치가 알아볼 수 있게 유지된다.
- [ ] 대형 건물·수면·도로가 임의로 추가되거나 사라지지 않는다.
- [ ] 아이소메트릭 카메라 방향과 축척이 장면 전체에서 일관된다.
- [ ] 사진풍 저해상도 이미지가 아니라 픽셀아트 문법이 보인다.
- [ ] 같은 설정의 반복 결과 중 사용할 수 있는 결과가 충분히 나온다.

권장 검증 자료:

- 원본과 결과의 나란히 비교
- 원본 edge를 결과 위에 반투명으로 올린 이미지
- 같은 설정의 seed별 contact sheet
- 실패 사례와 실패 사유
- 생성 횟수·시간·GPU 비용

### Gate 4 — 좌표 레이어 재결합 검토

확인할 것:

- [ ] POI와 지하철 마커가 `camera.json` 기준으로 투영되는가
- [ ] 마커가 가리키는 장소와 생성 배경의 시각적 대상이 과도하게 어긋나지 않는가
- [ ] AI 배경과 실측 좌표 레이어가 UI와 문서에서 구분되는가
- [ ] 라벨 밀도가 픽셀 배경을 가리지 않는가
- [ ] 기존 뷰어의 정확한 데이터 레이어가 손상되지 않았는가

### Gate 5 — 확대 여부 검토

대표 장면을 통과한 뒤에만 검토한다.

- [ ] 대표 장면의 총 생성량과 채택률이 기록되었는가
- [ ] 구간당 GPU 비용과 수동 검수 시간이 실측되었는가
- [ ] 전체 범위 예상치가 남은 일정과 예산 안에 들어오는가
- [ ] 인접 장면 또는 넓은 단일 장면에서 스타일 변화가 감당 가능한가
- [ ] 확대가 제출 문서 작성 시간을 침범하지 않는가

판정: 하나라도 불명확하면 전체 범위가 아니라 대표 장면 또는 부분 채택으로 제한한다.

## 6. 이미지 평가 기준

각 결과는 1~5점으로 평가한다. 점수만 쓰지 말고 근거를 한 문장 이상 남긴다.

| 항목 | 질문 |
|---|---|
| 시각적 매력 | 기존 렌더보다 탐험하고 싶은 장면으로 보이는가 |
| 장소 동일성 | 경복궁과 주변 도로를 같은 장소로 알아볼 수 있는가 |
| 도로 보존 | 주요 도로의 위치·연결·폭 관계가 유지되는가 |
| 랜드마크 식별성 | 궁궐 전각과 주요 시설이 일반 건물과 구분되는가 |
| 픽셀아트성 | 픽셀 크기, 윤곽, 팔레트, 명암이 의도적으로 통제되는가 |
| 장면 밀도 | 수목·창문·보도 등 디테일이 빈 공간을 자연스럽게 채우는가 |
| 환각 억제 | 없는 대형 객체가 생기거나 중요한 객체가 사라지지 않는가 |
| 반복 가능성 | 같은 설정으로 비슷한 품질을 다시 얻을 수 있는가 |
| 확장 가능성 | 비용과 검수량이 범위 확대 시 감당 가능한가 |

사용자 취향이 핵심인 시각적 매력의 최종 점수는 사용자가 정한다. Codex는 구조·재현성·권리·
확장성에 대한 근거를 제공한다.

## 7. 판정 등급

검토 결과는 다음 네 등급 중 하나로 보고한다.

### 그대로 진행

필수 조건이 충족되었고 다음 단계로 넘어가도 된다.

### 조건부 진행

핵심 가설은 유효하지만 다음 단계 전에 제한된 수정 또는 확인이 필요하다. 조건과 완료 증거를
구체적으로 적는다.

### 수정 필요

현재 결과로 다음 단계에 넘어가면 비용이나 일정 손실 가능성이 크다. 어떤 항목이 실패했고
어디까지 되돌아가야 하는지 적는다.

### 접근 중단

미감과 구조 보존을 함께 달성하지 못하거나 라이선스·비용·마감 조건을 충족할 수 없다.
기존 프로토타입, 부분 에셋, 대표 이미지 중 무엇을 보존할지 함께 제안한다.

## 8. 중단 조건

다음 중 하나가 발생하면 같은 접근의 추가 반복을 중단하도록 권고한다.

- 계획된 조정 횟수를 모두 썼는데 주요 도로와 랜드마크가 계속 무너진다.
- 대표 장면 한 장을 고르는 데 30장을 초과한다.
- GPU 비용이 사전 예산을 초과한다.
- 동일 설정을 기록해도 결과를 재현할 수 없다.
- 모델 또는 서비스의 출력 이용 권리를 명확히 설명할 수 없다.
- 09-08까지 단일 장면과 좌표 재결합의 실현 가능성을 판정하지 못한다.
- 09-16 이후에도 개발을 계속해야 제출 가능한 상태가 된다.

중단은 실패 은폐가 아니다. 조건 이미지와 실패 결과도 공간데이터 기반 생성 실험의 증빙으로
보존할 수 있다.

## 9. 변경 관리

- 계획 변경은 이유, 영향, 대체 산출물, 새 중단 시점을 함께 기록한다.
- 모델 변경 시 라이선스 검토를 다시 수행한다.
- 해상도·bbox·카메라 변경 시 기존 결과와 직접 비교할 수 없음을 표시한다.
- 선택 결과만 남기지 않고 후보와 실패 사례도 보존한다.
- 대용량 가중치·캐시·개인 키·토큰은 저장소에 넣지 않는다.
- 기존 사용자 변경사항과 Claude의 진행 중 변경사항을 감독 과정에서 되돌리지 않는다.

## 10. 감독 보고 형식

Codex의 검토 결과는 아래 순서로 간결하게 보고한다.

```text
판정: 그대로 진행 / 조건부 진행 / 수정 필요 / 접근 중단

핵심 근거
1. 확인된 사실
2. 성공 또는 실패 기준과의 비교
3. 일정·비용·라이선스 영향

필수 조치
- 다음 단계 전에 반드시 필요한 것

권장 조치
- 시간이 허용될 때 개선할 것

확인 범위
- 읽은 파일, 본 이미지, 실행한 검증
- 실행하지 않았거나 확인하지 못한 항목
```

발견 사항은 심각도가 높은 순서로 적고, 파일 위치나 산출물 이름을 함께 제시한다. 검토하지 않은
영역을 추측으로 통과시키지 않는다.

## 11. 최초 감독 의견

2026-09-04 계획 검토에서 다음 사항을 확인했다. 구현 전에 문서 또는 실행 설정에서 해소되어야 한다.

1. `README.md`는 자신을 기준 문서로 선언하지만 `PLAN.md`가 모델 수, 타일 검증, LoRA,
   최종 산출물 범위를 다르게 정의한다. 문서 우선순위를 일치시켜야 한다.
2. Qwen 실패가 SD+ControlNet 실패를 의미하지는 않는다. 모델 1종에서 중단하는 것은 기술적
   결론이 아니라 마감에 따른 범위 결정이라고 기록해야 한다.
3. Qwen 실행 경로가 `base_rgb + edge`, 조건 강도, denoise strength를 실제 지원하는지 확인해야 한다.
4. `LICENSES.md` 작성과 출력 이용 권리 확인을 GPU 추론보다 먼저 해야 한다.
5. 단일 컷 판정에는 도로 보존뿐 아니라 랜드마크 배치 보존과 미감 개선이 함께 포함되어야 한다.
6. 대표 장면은 전체 구현처럼 표현하지 않고, 기존 전체 뷰어와 구분된 PoC로 제출 문서에 표시한다.

이 항목들은 구현을 중단시키기 위한 것이 아니라, 비싼 추론을 시작하기 전에 실패 조건을 명확히
하기 위한 감독 체크포인트다.
