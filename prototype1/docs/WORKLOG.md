  이 공모전은 1차 통과 시 **대국민 공개검증 10일 이상 + 위반 시 입상 취소·환수**라 해석 다툼을
  안고 갈 수 없다. **Isopolis는 이 경로를 썼고 HN에서 지적받았다 — 따라하면 안 되는 지점.**

   용도별 스프라이트 매핑을 하려면 **국토부 GIS건물통합정보가 반드시 필요**하다.
   APPROACH.md의 A안이 전제한 "용도 속성으로 자동 매핑"은 이 데이터 확보에 달렸다.
2. **실측 높이가 없다.** 층수만 있어 `FLOOR_H = 3.0m`로 가정했다. `iso.py`에 상수로 빼뒀다.
3. **0층 건물이 50동(17%).** 부속건물로 보이며 1층으로 올려 처리했다.
4. **궁궐 전각이 납작한 상자로 나온다.** APPROACH.md §5에서 예측한 그대로 재현됐다.
   → 스프라이트 보강 없이는 경복궁이 "낮은 베이지 상자 밭"이다.
5. **WFS는 bbox에 걸친 피처 전체를 반환한다.** 경복궁 지정구역 폴리곤이 bbox 밖까지 뻗어
   자동 프레이밍이 끌려갔다. 프레임을 bbox로 고정하도록 고쳤다 (타일링에도 이 방식이 맞다).

## 2026-09-04 — Phase 2 재구성: "픽셀아트답게" + 랜드마크 방식 확정

### 계기: 지금 결과물이 픽셀아트가 아니다

사용자 지적. 확인해보니 **계획이 원인의 절반만 덮고 있었다.**
원래 Phase 2는 "AI 스프라이트"만 다뤘는데, 진짜 원인은 텍스처가 아니었다.

| 원인 | 기존 계획에 있었나 |
|---|---|
| **① 픽셀 격자 부재** | ❌ **없음. 근본 원인** |
| ② 팔레트 제한 없음 | ❌ 없음 |
| ③ 표면 텍스처 없음 | ✅ 있음 |

**①이 핵심이다.** `poc/iso2.py`는 작게 그린 뒤 `Image.NEAREST`로 정수배 확대해
픽셀 경계가 살아 있다(`ZOOM=3`). 그런데 **브라우저 뷰어는 화면 해상도에 바로 그려서 이걸 잃었다.**
`imageSmoothingEnabled=false`는 이미지 확대에만 걸리고 Canvas 도형의 안티앨리어싱은 못 막는다.
→ **뷰어가 파이썬 렌더러보다 덜 픽셀아트다.** ②로 옮기며 잃은 것을 내가 짚지 못했다.

**해법**: 오프스크린 캔버스(1/N)에 그린 뒤 정수배 NEAREST 확대.
부수 효과로 렌더 면적이 1/N²이라 112ms가 20ms 아래로 떨어진다.

### Phase 2를 6단계로 재구성

- **2-A 픽셀 격자 복원** ← 최우선. 반나절. 효과 최대
- 2-B 팔레트 32~48색 제한 + 디더링
- 2-C 지붕 기하 절차적 생성 (맞배/팔작) — **AI 아님**
- 2-D 표면 텍스처 — **여기가 AI 담당**
- 2-E 랜드마크 형식 지정
- 2-F JS 렌더러 반영

**순서를 바꾼 이유**: 2-A/2-B를 먼저 하면 텍스처 없이도 즉시 픽셀아트처럼 보인다.
기존 계획은 2-D(AI 텍스처)부터 하게 돼 있었다.

### 형태 / 외형 역할 분담 확정

| 구성 | 어디서 | AI |
|---|---|---|
| 형태(바닥·높이·위치) | `dt_d198` | ❌ 좌표를 건드리지 않는다 |
| 지붕 기하 | 절차적 생성 | ❌ AI보다 정확하고 싸다 |
| 표면 텍스처 | AI 스프라이트 | ✅ |
| 랜드마크 외형 | 형식 지정 + 절차적 생성 | ❌ |

### 랜드마크: 방식이 두 번 바뀌었다 (최종: AI 변환)

**1차** — "수제 스프라이트"라고 적었으나 표현이 모호했다.

세 가지로 갈린다.
1. 사람이 픽셀 에디터로 그림 — 전각 1개당 1~3시간, 15개면 20~40시간
2. 형식을 파라미터로 지정하고 렌더러가 그림
3. AI

**사용자가 "직접 그리는 건 현재 시점에서 불가능"하다고 확인 → ① 탈락, ②로 잡았다.**

**2차 (최종)** — 사용자가 "AI를 쓰는 게 나을 것 같다"고 제안. **재검토 결과 맞는 지적이었다.**

내가 ②를 과대평가했다:
- **임의 footprint에서 팔작지붕을 정확히 만들려면 straight skeleton이 필요하다.**
  이걸 "쉽다"고 잡은 것이 오판이다. D-14에 감당할 기하 문제가 아니다
- 분야가 **GeoAI**인데 AI 비중이 텍스처뿐이면 정합성이 약하다
- ②로 나오는 근정전도 결국 "중층 팔작 상자"라 정확성 우위가 생각만큼 크지 않다

**내가 걱정한 "틀린 근정전"은 참조 이미지로 해결된다.**

**국가유산청이 문화유산 사진을 OpenAPI로 개방하고 공공누리 라이선스다** (48만 건 무료 개방).

```
국가유산청 개방 사진 (근정전 실물)
   -> Qwen-Image-Edit 로컬 실행 (image-to-image)
   -> 아이소메트릭 픽셀아트 스프라이트
   -> 사람이 10~15개 실물과 대조
   -> buld_nm 매칭 배치
```

**핵심은 "생성"이 아니라 "변환"이라는 점이다.**
"한국 궁궐을 그려줘"는 상상한 궁궐을 낳지만, **실물 사진을 입력으로 주면 그건 근정전이다.**
Qwen-Image-Edit가 원래 image-to-image 모델이라 정확히 이 용도다. 출처도 국가유산청으로 댈 수 있다.

**부수 효과**: V-World(공간정보) + 국가유산청(문화유산) 두 국가 데이터를 AI로 결합하는
구조가 되어 데이터 다양성·수급성에도 기여한다.
그리고 **팔작지붕 절차적 생성 문제가 통째로 사라진다** — 2-C는 일반 한옥 맞배지붕만 맡는다.

**확인해야 할 것 (Phase 2 첫날)**
1. **사진→아이소메트릭 각도 불일치.** 사진은 정면·사각, 우리 투영은 방위 22.5°/고도 30° 고정.
   변환 품질이 관건이라 **1개로 먼저 검증**한다
2. 국가유산청 API에 근정전·경회루·광화문 사진이 실제로 있는지, 해상도가 쓸 만한지 미확인

**실패 시 후퇴**: ②(형식 파라미터 + 절차적 생성)로 되돌린다. 지붕은 팔작 대신 단순화.
이 경로는 문서에 남겨둔다.

**"실측 기하는 그대로 두고, 데이터에 없는 양식만 AI가 채운다."**
"AI로 서울을 복원했다"는 과장은 정확성 심사에서 역풍이다.

### 프레임워크: **넣지 않는다 (vanilla 유지)**

현재 정적 파일 6개, 빌드 없음, 의존성 0. 이미 배포 가능한 상태다.
프레임워크를 넣으면 **순수 비용**이다.

UI가 이보다 크게 복잡해질 계획도 없다. 필요해지면 그때 넣어도 늦지 않다.

### 호스팅: **Cloudflare Pages 추천**

|---|---|---|---|---|
| **Cloudflare Pages** | ✅ | ✅ | ✅ | ✅ 무료 |

**Cloudflare Pages를 고르는 이유**

   **제출 전에는 비공개가 안전하다** — 요강에 표절 시 입상 취소 조항이 있다

## 2026-09-04 — Phase 2-A 완료: 픽셀 격자 복원

### 무엇을 바꿨나

**아트 픽셀 좌표계를 도입했다.** 1/PIX 크기 오프스크린 캔버스에 그린 뒤
정수배 NEAREST로 확대해 화면에 붙인다. `poc/iso2.py`가 `Image.NEAREST`로 하는 것과 같다.

```
이전: 화면 해상도에 직접 그림     -> Canvas 안티앨리어싱, 가장자리가 뭉개짐
이후: 오프스크린(1/3)에 그림 -> 3배 NEAREST 확대 -> 픽셀 경계가 살아남
```

좌표계가 둘이 됐다.
- **아트 픽셀** — 오프스크린. `sx`/`sy`가 돌려주는 값. `s()`는 "미터/아트픽셀"
- **화면 픽셀** — 아트 픽셀 × PIX. 입력 이벤트와 라벨이 쓴다

`PIX`는 `poc/style.json`의 `pixel_size`(기본 3)에서 읽는다.
`SCALES`도 "미터/화면px"에서 **"미터/아트픽셀"**로 의미가 바뀌어 `[8, 4, 2, 1, 0.5]`로 재조정했다.

### 결과

| | 이전 | 이후 |
|---|---|---|
| 전체 6,991동 | 112ms | **81ms** |
| 확대 시 | 46ms | **24~48ms** |
| 가장자리 | 안티앨리어싱 | **계단식 픽셀** |

**렌더 면적이 1/9이라 더 빨라졌다.** 라벨은 화면 해상도 별도 레이어로 그려 선명함을 유지했다.

### 함께 고친 것

1. **기호 크기 고정** — 지하철 선·역·POI 마커가 월드 크기라 확대할수록 굵어졌다.
   기호는 물리적 대상이 아니므로 아트픽셀 기준 고정값(`SYM`)으로 바꿨다.
   지하철역은 원 대신 **픽셀 사각형**, POI는 한 줄씩 쌓은 **픽셀 삼각형**으로 그린다.
2. **건물 클릭이 지붕에서만 되던 문제** — 벽면을 클릭하면 안 잡혔다.
   압출은 화면상 수직 이동이므로 실루엣은 지붕 폴리곤을 아래로 쓸어내린 영역이다.
   높이 구간을 최대 6단계 샘플링해 벽면도 잡도록 고쳤다.
3. **선택 처리를 `pointerup`에서 `click`으로 이동** — 포인터 캡처 상황에 따라
   `pointerup`이 누락될 수 있다. `setPointerCapture`도 try/catch로 감쌌고
   `pointercancel`도 처리한다. 포인터 이벤트는 팬만 맡는다.
4. **자체 검증 추가** — `window.pixelCitySelfCheck()`로 점-내부 판정, 처마 확대,
   오프스크린 크기, 화면중심 역투영을 확인한다. 디버그 훅 `window.pixelCity`도 노출했다.

### 검증

- 투영 골든 값 5건 일치 (변경 후에도 유지)
- `pixelCitySelfCheck()` 통과
- 합성 이벤트로 **건물(국립고궁박물관) / 지하철역(경복궁역) / POI(국토발전전시관)** 세 종류 클릭 확인
- 콘솔 오류 0건

⚠️ **브라우저 자동화 도구의 마우스 클릭이 캔버스에 닿지 않아 실제 마우스 검증은 못 했다.**

## 2026-09-04 — Phase 2-B 완료: 팔레트 양자화

### 문제 확인

픽셀 격자를 넣었는데도 경계가 완전히 딱 떨어지지 않았다.
**오프스크린 캔버스도 도형을 안티앨리어싱**하기 때문이다.
실측으로 확인했다 — 지도 영역만 색 수를 세니 **693색**이 나왔다
(팔레트로 정의한 색은 57개뿐인데).

`imageSmoothingEnabled = false`는 **이미지 확대**에만 걸린다.
Canvas의 `fill()`/`stroke()` 경로 렌더링에는 적용되지 않는다.

> 참고: 파이썬 렌더러(`poc/iso2.py`)는 PIL이 폴리곤을 안티앨리어싱하지 않아
> 이 문제가 없다. **브라우저 전용 보정이다.**

### 해결

렌더 후 blit 직전에 오프스크린 픽셀을 팔레트의 가장 가까운 색으로 스냅한다.

- `buildPalette()` — `style.json`의 색을 모으고 **처마 파생색**(`×0.72`, `×0.62`)도 포함한다.
  이 파생색을 빼면 처마가 엉뚱한 색으로 스냅된다
- `nearest()` — 15비트 RGB 키(`r>>3, g>>3, b>>3`)로 **32,768칸 LUT를 지연 캐싱**한다.
  캐시 없이 매 픽셀 57색과 거리 계산을 하면 프레임당 수백만 연산이 된다
- `quantize()` — `getImageData` → 치환 → `putImageData`
- **픽셀화를 끄면 양자화도 건너뛴다** (`PIX > 1`일 때만)

### 결과

| | 이전 | 이후 |
|---|---|---|
| 지도 영역 색 수 | 693 | **43** |
| 팔레트 정의 | — | 57색 |
| 전체 뷰 렌더 | 81ms | **102ms** |
| 확대 시 | 24~48ms | **31~79ms** |

양자화 비용은 **약 +20ms**다. 되돌리기 기준(줌 전환 1.5초)의 1/15이라 문제없다.
처음 150ms가 나온 것은 LUT warmup이었고 정상 상태는 위 수치다.

**경계에서 중간색이 완전히 사라졌다.** 확대해서 보면 계단이 또렷하다
(`docs/img/viewer-palette-gyeongbokgung.jpg`).

### 디더링은 넣지 않았다

계획서에는 "팔레트 제한 + 디더링"으로 적었으나 **디더링할 대상이 없다.**
모든 면이 단색 채우기라 계조가 존재하지 않는다. 디더링을 넣으면 의미 없는 노이즈만 생긴다.
벽면 질감은 **Phase 2-D 스프라이트**가 맡는 것이 맞다.
